# Shipi18n Vue Example

A Vue 3 + [vue-i18n](https://vue-i18n.intlify.dev/) app whose locale files are translated **during the Vite build** by [`vite-plugin-shipi18n`](https://www.npmjs.com/package/vite-plugin-shipi18n), using your own OpenAI or Anthropic key.

Because Vue projects are usually Vite projects, the plugin is the least intrusive integration: add it to `vite.config.js` once and translation becomes part of the build.

## The important part: no key in the browser

```js
// vite.config.js
shipi18n({
  provider: 'anthropic',
  targetLanguages: ['es', 'fr', 'de'],
  sourceDir: 'src/locales/en',
  outputDir: 'src/locales',
})
```

The plugin runs in Vite's `buildStart` hook — on your machine or your CI runner, before the bundler. Your key is never part of the output.

**Never** put an LLM key in a `VITE_`-prefixed variable: Vite inlines those into the bundle by design, publishing it to every visitor. An earlier version of this example used `VITE_SHIPI18N_API_KEY`, which is why it was restructured.

## Quick Start

```bash
git clone https://github.com/Shipi18n/shipi18n-vue-example.git
cd shipi18n-vue-example
npm install

cp .env.example .env      # then set ANTHROPIC_API_KEY
npm run build             # the plugin generates es/fr/de
npm run dev
```

Generated files are committed, so `npm run dev` works without a key.

## Structure

```
src/
├── locales/
│   ├── en/translation.json   # the only file you edit
│   ├── es/translation.json   # generated by the plugin — commit these
│   ├── fr/translation.json
│   └── de/translation.json
├── i18n.js                   # vue-i18n setup, lazy-loads each locale
├── components/
│   └── LocaleSwitcher.vue
└── App.vue
```

Every locale — English included — loads through the same `import.meta.glob`, so each language is its own chunk and a visitor downloads only what they switch to. Loading English the same way also avoids Vite's "statically and dynamically imported" warning.

## vue-i18n syntax notes

Two things differ from i18next, and both matter when the strings go through a model:

**Interpolation is single-brace.** `{name}`, not `{{name}}`. Keep your source file in vue-i18n syntax and it comes back unchanged — the engine recognises both.

**Plurals are one pipe-separated string**, not `_one` / `_other` keys:

```json
{ "items": "You have {count} item | You have {count} items" }
```

```js
t('items', count, { count })   // picks the form
```

The pipe survives translation:

```
es: "Tienes {count} elemento | Tienes {count} elementos"
fr: "Vous avez {count} élément | Vous avez {count} éléments"
```

There is a test asserting exactly this, because if a model ever ate the `|` the plural would silently collapse to one form — and you would not notice until a customer did.

## Caching

Results are cached in `node_modules/.cache/vite-plugin-shipi18n`, so a rebuild with unchanged strings makes no model calls. Delete that directory to force a full re-translation.

To skip translation when no key is present — CI, a contributor's laptop — gate the **plugin**, not the language list. An empty `targetLanguages` throws:

```js
const translate = process.env.ANTHROPIC_API_KEY
  ? [shipi18n({ provider: 'anthropic', targetLanguages: ['es', 'fr', 'de'] })]
  : []

export default defineConfig({
  plugins: [vue(), ...translate],
})
```

Because the generated files are committed, a keyless build simply reuses them.

## Tests

```bash
npm test
```

14 tests, no key or network needed: every generated file matches `en` key for key, `{placeholders}` survive, the pipe plural keeps both forms, translations are not copies of English, and the source file uses vue-i18n syntax rather than i18next's.
